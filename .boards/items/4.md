The customer-facing setup flow: pick **(a) overall structure**, **(b) fonts**,
**(c) colour scheme**, independently of each other. Most of this already exists inside
Live Spirit Seeds and is in better shape than expected — the work is generalising it and
splitting one welded axis in two.

## (a) Structure — mostly renaming

The LSS UX styles, **minus the original**: ship `editorial`, `sanctuary`, `immersive`.
(`watercolor` is the untouched baseline — `body.style-watercolor` deliberately matches
nothing in `src/styles/ui-styles.css`.)

A style is **~98% CSS**. Exactly one component branches on it in JS:
`src/components/Nav.jsx`, via `useUiStyle()` and a `data-nav-variant` attribute that
`Nav.module.css` keys 14 rules off. The splash block is style-*differentiated* but not
style-*aware* — `SplashSection` emits one fixed skeleton driven by content
(`taglinePlacement`, `overlayAlign`) that all four styles restyle purely in CSS.

Note the CSS-module split that has to be preserved: the **layout** of the nav bar lives
in `Nav.module.css` keyed off `[data-nav-variant]`, the **paint** in `ui-styles.css` via
`nav:has(h1)`, because module classes are hashed and unreachable from the global sheet.

## (b) Fonts — this is the actual work

Fonts are currently **welded to structure**: `editorial`→Fraunces, `sanctuary`→Playfair
Display + Caveat, `immersive`→Cormorant Garamond, `watercolor`→Euphoria Script + Farsan.
Body is Merriweather Sans in all four.

Making fonts independent means lifting `--font-heading` / `--font-subheading` out of
`ui-styles.css` into a `font-<name>` body class set independently of `style-<name>`.
Two consequences:

- **Some structure rules are tuned to their font's metrics** and will need loosening —
  the per-style `h2` clamps and letter-spacing were chosen against a specific face.
- **All seven families load from one Google Fonts URL** (`src/styles/index.css` line 6),
  so every visitor pays for all seven today. An independent font axis makes that worse.
  **Per-selection font loading has to land with this item**, not after it.

## (c) Colour — in excellent shape

Generalise the four seasons into arbitrary named palettes. `src/styles/themes.css` is
**exactly 12 custom properties and zero structural rules** — verified; a grep for the
season classes across `src/` hits only that file. Season → structure leakage is nil.

The 12: `--primary-color`, `--text-color`, `--secondary-color`, `--bg-color`,
`--bg-color-light`, `--text-outline-color`, `--gradient`, `--gradient-reverse`,
`--navbar-background`, `--section-bg-image`, `--tagline-hue`, `--blossom-icon`.

Note the last four are **assets**, not colours — a generalised palette needs an answer
for image slots, or those move to a fourth axis.

Also: spring is declared on `:root`, not `.spring` — `applyTheme('spring')` adds a class
matching nothing and works only because the other three were removed. Same null-case
pattern as the modes primitive (item 2); make it explicit rather than incidental.

## Leaks to clean while generalising

"A style never sets a colour" is currently a **convention, not an invariant**. Four
categories, all achromatic or defensible, all needing a decision:

1. Hardcoded `#fff` / `rgba(255,255,255,…)` on splash overlay type — ~10 sites in
   `ui-styles.css` plus `.splash__content` in `layout.css`. Text on a photograph, so
   arguably correct, but it is literal colour in the structure layer.
2. **Shadow colour baked into the composite `--shadow-*` tokens** — `rgba(40,28,14,…)`
   for editorial/sanctuary, `rgba(0,0,0,…)` for immersive. Unavoidable while shadow is
   one token; splitting colour out of it is the fix.
3. The immersive vignette, `rgba(20,14,8,.16/.28)` — the code comments already defend
   this as structural scrim rather than palette.
4. **Styles reassign colour *roles*** — sanctuary puts `--primary-color` on `h3`;
   `Nav.module.css` per-variant CTA rules assign `--primary-color` / `--bg-color-light`.
   The hue always comes from the palette, but *which element gets which token* is
   decided by the structure axis. This one is real coupling, not a nit.

## Preview is nearly free

`src/utils/preview.js` + the exported `applyTheme`/`applyUiStyle` in `src/cms/site.js`
are already pure DOM functions behind a whitelist, and `src/utils/useUiStyle.js` already
re-renders style-aware components from a `MutationObserver` on the body class — so a
chip tap restyles the nav live with no reload. Two fixes before an editor can drive it:

- **`sessionStorage` is shared by same-origin iframes**, so the `'ssw:preview'` key would
  collide between an editor shell and the site embedded inside it. Namespace it or move
  to `postMessage`.
- **`initPreview` reads `window.location.search` exactly once**, in a mount-only effect,
  not via react-router's `useLocation`. Fine for entry-only params; a URL-driven editor
  needs that hoisted to a location-reactive effect.

A site mode is a named axis of presentation that reskins the whole page. Three sites
ship one and each re-derived the same bookkeeping:

| | edgeOfTheMap | Live Spirit Seeds | StoryShaped |
| --- | --- | --- | --- |
| Lives on | `<body>` **and** a `.face` wrapper | two `<body>` classes | React context + `data-mode` on a page wrapper |
| Persists | not at all | CMS + sessionStorage (preview) | localStorage |
| First paint | no flash (light is the default) | `visibility:hidden` + build-time bake | synchronous read before first render |
| Transition | 1.8s burn | instant | 0.6s CSS |
| Count | fixed 2 | 4 × 4, enumerated | fixed 2 |

All three reduce to **read initial value → write DOM → persist**, differing only in the
source of truth.

## Done

`src/useSiteMode.js` in this repo, adopted by `App.jsx` for the face axis with
`persistence: 'none'` — no behaviour change. Rules encoded: the value list is declared
once and derives the validator/strip-set/cycle order; the first value is the null case
and takes no class; scope can be an element rather than only `<body>`; persistence is
an explicit choice. Recorded in DESIGN.md §3 and ADR 0005.

## Remaining

- **Adopt in Live Spirit Seeds.** Two axes (`season`, unprefixed; `uiStyle`, prefixed
  `style-`). It currently duplicates `SEASONS`/`UI_STYLES` across `src/main.jsx` and
  `src/cms/site.js`, which the primitive's single list fixes. Needs a `remote` adapter
  for the CMS-backed durable value, layered under the existing sessionStorage preview.
- **Adopt in StoryShaped.** One axis, `localStorage`, currently a React context. Note
  the per-page opt-in is already broken — `src/pages/Shop/index.jsx` renders no
  `.sss-home` wrapper and sits entirely outside the theme. Also `documentElement.dataset.mode`
  is written but no CSS reads it; decide whether that becomes the real hook or goes.
- **Where it lives.** Copying one file into three repos is worse than the duplication
  it fixes. It should become a module in the platform repo (item 3) and be consumed
  from there.

## Deliberately out of scope

Assets and transitions. Tokens cannot recolour a bitmap and all three sites answered
that differently (layer split + hue token / `mix-blend-mode: screen` + `hue-rotate` /
mode-independent artwork); there is no common mechanism, only a question each mode must
answer. Transitions and their reduced-motion degradation belong to the site. See ADR 0005.
